# Auto Calculate solver

`js/auto-calculate-solver.js` replaces the former first-valid-candidate behavior with a deterministic best-arrangement search. It does not use machine learning and it never marks a pole UG or PCO automatically.

## Supported modes

### TOP COMM

The ideal pole attachment is:

```text
Proposed = Top Comm + Pole Comm-comm clearance
```

The solver first tries to keep existing comms in place. When the ideal Proposed does not fit, it builds the smallest downward stack permitted by Pole Comm-comm and Pole Bolt-bolt rules.

### LOW COMM

The ideal pole attachment is:

```text
Proposed = Low Comm - Pole Comm-comm clearance
```

When more room is required, the solver builds the smallest upward comm stack while respecting the pole maximum and all existing validation rules.

## Candidate heights

All calculations use integer inches. The solver evaluates exact one-inch candidates around the ideal position and important rule boundaries, plus wider six-inch checkpoints. Important boundaries include:

- the ideal TOP COMM or LOW COMM position;
- Max Height on Pole;
- current Proposed values;
- Existing HOA and current effective HOA values;
- Comm-comm and Bolt-bolt offsets.

The solver does not test fractional inches and does not scan every physically impossible height.

## Result priority

Candidate arrangements are compared lexicographically in this order:

1. Result category.
2. Number of pole violations.
3. Total pole violation shortfall.
4. Number of Midspan violations.
5. Total Midspan violation shortfall.
6. Number of comm groups moved.
7. Total movement in inches.
8. Distance from the ideal Proposed position.

The categories are:

| Status | Meaning |
| --- | --- |
| `SAFE` | Pole and Midspan rules both pass. |
| `BEST_AVAILABLE` | Pole rules pass, but one or more Midspan rules remain. |
| `CRITICAL` | No pole-compliant aerial arrangement was found; the best evaluated arrangement is retained. |
| `MANUAL` | Required calculation data is missing. |
| `SKIPPED` | No eligible Proposed span exists, or the pole is already UG/PCO. |

A pole-compliant result always outranks a result that fixes Midspan while leaving a pole violation. This is intentional even when the remaining Midspan shortfall is larger.

## Existing validation remains authoritative

For every candidate, the solver applies the proposed heights to a clean state copy and invokes the existing calculation and validation APIs. It uses the resulting Pole, Proposed and Midspan flagging messages to measure the candidate. The solver does not maintain a second independent clearance rule set.

## User-entered values

A user-entered `HOA Change` is locked during Auto Calculate. A user-entered `Proposed HOA` is also preserved. Values generated by Auto Calculate are marked with `AUTO` source metadata and may be replaced during a later run.

## Network recalculation

Each candidate recalculates the selected pole, connected endpoints and matching Wire IDs. The complete job is processed for up to three passes and stops early when the movement/Proposed signature converges or repeats.

## UG and PCO

For INTEC, `BEST_AVAILABLE` and `CRITICAL` results display a recommendation to review UG or PCO. The solver does not select either option. Existing UG/PCO poles are skipped and keep their user-selected resolution.

## Deferred actions

Streetlight Ground/Raise, Transformer Redress, Power Riser Raise, Re-sag and Transfer remain user-controlled actions in this version. Their active values still participate in normal recalculation and candidate validation. A future solver stage may evaluate them as explicit optional actions, but it must continue to show and require confirmation before applying construction decisions.
